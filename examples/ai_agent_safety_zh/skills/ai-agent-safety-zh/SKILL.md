# AI 智能体安全 — 领域简报

两个独立项目共享同一领域：一份带来源的 **AI 安全情报摘要**，以及一份可落地的 **AI 智能体护栏架构**。各自独立完成证明，互不等待。

以下是在内置 Plan / Supervise / Execute 契约之上的领域提示。

## 输出语言

所有产出一律使用**简体中文**：Intent 描述、Fact 摘要、Hint 内容，以及 Artifact 报告（Markdown 正文、标题、表格与说明）。专有术语可保留英文原词（如 prompt injection、sandboxing、NIST AI RMF），但叙述、分析与结论一律用中文。

## 当前 AI 安全版图（以 2024–2026 为"当前"）

- **对齐与可解释性：** 引导（steering）、监督（oversight）、可扩展监督、欺骗性对齐、机制 / 行为可解释性。
- **智能体安全：** 提示注入（直接与间接）、工具与数据外泄、越权、越狱、智能体供应链攻击。
- **评测与红队：** 自动化红队、能力探测、拒绝 / 过度拒绝、沙箱化评测。
- **事件：** 已披露的模型与智能体故障、攻击手法、事后复盘。
- **标准与政策：** NIST AI RMF / AISI、欧盟 AI 法案 + GPAI 行为准则、ISO/IEC 42000、前沿模型框架。

## 来源质量

优先一手来源：论文、官方标准 / 监管文本、厂商与安全公告、事后复盘、持续维护的开源仓库。转贴、盘点文和营销内容只用作线索——在采信前先追溯一手来源。

## 设计可落地的护栏架构

护栏设计不是清单——每一项控制都必须对应到一个威胁：

- 先做**威胁建模**：资产、信任边界、参与者、滥用场景、风险分级。
- 覆盖各控制层：身份 / 认证 / 委托 · 工具与数据边界（最小权限、密钥）· 沙箱 / 隔离（网络、文件系统、进程）· 策略闸门与配额 · 运行时遥测 / 异常检测 · 审计 · 应急响应。
- 每项控制写明：它阻断的失效模式、负责人、证明其生效的遥测，以及验收测试。
- 区分预防、检测、响应、恢复四类控制。
